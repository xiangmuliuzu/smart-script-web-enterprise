# PC 企业端原型还原验证（2026-10-15）

项目：smart-script-web-enterprise。原型文件 `剧云策-企业端原型.html` 保持原样，未修改。

## 交付

按原型在浏览器里执行完所有初始化脚本后的**最终渲染状态**重建主体页面：单一视图「采购工作台」`/dashboard`，发现剧本、我的购买作品、交易中心已按原型最终态改为顶栏入口与浮层，不再是路由。原型 6 个 `<style>` 块原样合并进 `src/assets/styles/prototype.css`，Element Plus 主题桥接在 `src/assets/styles/portal.css`。

浮层：交易中心抽屉（询盘 / 报价 / 订单 / 合同）、消息抽屉、沟通页、作品详情页、章节试读弹层、订单与合同详情弹层、个人资料抽屉、意见反馈抽屉。

页面只调用普通用户域接口（`/api/v1/trade/*`、`/api/v1/content/*`、`/api/v1/messages`、`/api/v1/users/me/*`、`/api/v1/feedback`）。后端没有面向用户侧的合同、交付、企业工商信息接口，相应位置显示「服务尚未开放」，不调用 `/api/v1/admin/*`、不伪造成功状态。金额口径：订单 `amount` 是分，报价 `price`、询盘 `budget`、作品 `price` 是元。

## 自动验证

`npm run gate`：11 项 Node 测试全部通过；Vite 生产构建成功（1616 modules，主包 1,055 kB / gzip 339 kB）。

`compare.mjs`：Playwright 在同一视口、同一缩放、同一登录状态下，对原型与项目各截 11 个状态并并排输出。断言 `admin calls: none` 与 `errors: none` 全部通过。同视口关键几何逐项比对一致，差异仅为固定 10px 滚动偏移：topbar 0,0×1440×68；`.split` 网格 `915.75px 416.25px`；面板 x42 w916；筛选栏 y184 h65；卡片首格 `112px 155.906px` h190；右栏 x982 w416。1544px 下两侧「作品采购」均为三列 279.078px。

响应式：1050/820px 转两列，720/390px 转一列，均无横向溢出。

## 修复记录

- 交易中心抽屉面板空白：`@click="openTrade"` 把原生事件当面板参数传入，改为 `openTrade()`。
- Escape 过度关闭：原型只关作品详情弹层、订单/合同弹层与 4 个 legacy 抽屉，不关消息页与沟通页，已对齐。
- 合同详情弹层被短路，补齐 `open-contract` 事件链。
- 「打开沟通」不建会话：改为先 `POST /api/v1/trade/inquiry/chat/sessions?inquiryId=`。
- 登录页多出原型没有的「忘记密码？」行，已删除。（2026-10-18 更新：按原型 link-row「注册个人账号 / 忘记密码」恢复为可用入口，点击后在登录卡片内切换为注册 / 找回面板，不再是无效行。）
- 头像失效时破图图标溢出圆形：容器补 `overflow: hidden`，`<img>` 加 `@error` 回落汉字圆标。
- 主内容被原型 `main{max-width:1480px}` 限宽而创作者端占满：`.portal-main` 覆盖为 `max-width:none`，与创作者端一致。
- 顶栏「消息」由原型遗留的居中浮层改为与创作者端一致的右侧抽屉（430px、贴右、无圆角）。
- 个人资料实名认证接入真实后端（`/api/v1/users/me/real-name` 与 `/material`）；此前实名材料上传会误清已填姓名与证件号，导致请求未发出，已修。
- 后端 `ruoyi-admin.jar` 早于订单域提交，`GET /api/v1/trade/order/list` 一直 404；重新打包后恢复正常。

## 联调边界

浏览器业务接口联调使用真实后端（127.0.0.1:8080）与真实注册账号，覆盖登录、工作台、发现剧本与作品详情、真实发起询盘、交易中心四页签、消息抽屉、沟通页、订单与合同弹层、个人资料与实名认证全流程。验证账号及其数据已清理，数据库回到基线（sys_inquiry 10 / sys_quote 11 / sys_order 16 / sys_user 145 / sys_chat_session 8）。

合同、交付、资金与企业工商信息目前只有管理端或不完整用户契约，相应位置显示「服务尚未开放」；发现剧本的授权方式一列因 `AppWorkDto` 无 `licenseType` 字段，按真实字段展示，不硬编码原型演示值。
